## Function: setup_modellauncher

### Refactor Summary

| Aspect | Old | New |
|---|---|---|
| Parameters | `setup_modellauncher(run, rundir, host_rundir, mpirun, binary)` | Split into artifact build plus explicit writer phases; current public helper remains a compatibility wrapper around those responsibilities |
| Load files | No meaningful load contract; behavior was bound to filesystem state implicitly | No strict-path file load; artifact content is built from explicit inputs |
| Save files | Deleted/recreated `joblist.txt`, wrote `launcher.sh`, and returned an open writable connection | Returns structured artifact object plus explicit `files_written` and `joblist_entries` |
| Settings-derived inputs | Reached from caller state that still depended on full workflow settings | Uses only explicit modellauncher inputs supplied by `start_model_runs()` |
| Flow | Deletes/recreates `joblist.txt`, writes `launcher.sh`, and returns an open writable connection | Build artifact payload first, then write launcher/joblist files explicitly and return written paths and artifact metadata |
| Return | Open file connection | Structured artifact object plus `files_written` and `joblist_entries` |
### Test Refactor

| Test area | Legacy coverage | Required update |
|---|---|---|
| Happy path | Indirectly exercised only through run-launch workflows | Add tests that artifact construction and writing are explicit and return written paths |
| Edge cases | File recreation behavior was hidden inside the helper | Add tests for existing `joblist.txt` replacement and launcher path generation |
| Side effects / integration points | Side effects were coupled to open connection state | Assert wrapper-only file writing and returned artifact metadata instead of hidden connection state |

### Call Flow Comparison

Old flow:

```text
setup_modellauncher(...)
  -> delete/recreate joblist.txt
  -> write launcher.sh
  -> return open file connection
```

New flow:

```text
.build_modellauncher_artifacts(...)
  -> create launcher content + joblist entries
.write_modellauncher_artifacts(artifacts)
  -> write launcher.sh and joblist.txt
  -> return files_written + artifact metadata
```

## Function: start_rabbitmq

### Refactor Summary

| Aspect | Old | New |
|---|---|---|
| Parameters | `start_rabbitmq(folder, rabbitmq_uri, rabbitmq_queue)` with hidden environment reads | `start_rabbitmq(folder, rabbitmq_uri, rabbitmq_queue, prefix = "", port = 15672)` |
| Load files | No file load, but runtime configuration was loaded implicitly from environment variables | No implicit environment-derived load in the strict path; runtime config is passed explicitly |
| Save files | No save-file contract; returned submission response only | Same response contract; no hidden persistence added |
| Settings-derived inputs | Reached via caller logic that implicitly depended on broader host/runtime settings | Uses only explicit runtime values supplied by `start_model_runs()` |
| Flow | Read `RABBITMQ_PREFIX` and `RABBITMQ_PORT` from the environment inside the helper | Receives runtime prefix and port explicitly from the caller in the strict path |
| Return | Submission response only | Same core submission response, but runtime configuration is explicit and testable |
### Test Refactor

| Test area | Legacy coverage | Required update |
|---|---|---|
| Happy path | Covered indirectly through run-launch workflows | Add tests that explicit prefix and port are honored |
| Edge cases | Environment fallback was implicit and unbounded | Add tests for missing explicit values vs temporary compatibility fallback behavior |
| Side effects / integration points | Runtime config dependency was hidden | Assert no hidden environment-variable dependency in the strict path |

### Call Flow Comparison

Old flow:

```text
start_rabbitmq(folder, rabbitmq_uri, rabbitmq_queue)
  -> read RABBITMQ_PREFIX and RABBITMQ_PORT from environment
  -> submit rabbitmq work
```

New flow:

```text
start_rabbitmq(folder, rabbitmq_uri, rabbitmq_queue, prefix = "", port = 15672)

  -> submit rabbitmq work
```
